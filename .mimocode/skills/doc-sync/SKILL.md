# TGWS文档同步技能

## 核心规则

### 文档职责划分

| 文档 | 职责 | 何时读取 |
|------|------|----------|
| **MEMORY.md** | 真实状态源 | 展示待办、进度、配置、悬停信息时 |
| **AGENTS.md** | 规则约束源 | 查阅开发约束、架构、工具使用规则时 |
| **PRD** | 设计权威源 | 查阅功能需求、设计规范时 |

### 关键教训

**绝对不能从AGENTS.md的Open Items获取待办信息** - 那是PRD阶段的原始设计，很多已解决但未更新。

**正确做法**：展示待办时，必须从MEMORY.md的"待办"部分获取。

## 展示待办的标准流程

### 1. 读取MEMORY.md待办部分

```
位置：MEMORY.md → "## 待办（SXX最新）"部分
包含：待执行、悬停、历史遗留
```

### 2. 验证状态

```
检查：待执行任务是否最新
检查：已完成任务是否标记
检查：悬停原因是否仍然有效
```

### 3. 展示格式

```markdown
## 待执行
| 任务 | 说明 |
|------|------|
| ... | ... |

## 悬停（不动）
| 任务 | 原因 |
|------|------|
| ... | ... |

## 历史遗留
- ...
```

## 文档同步检查清单

当执行文档同步时，检查以下内容：

- [ ] AGENTS.md Open Items是否与MEMORY.md一致
- [ ] PRD [S22]状态是否与MEMORY.md一致
- [ ] MEMORY.md待办是否标记最新状态
- [ ] 是否有过期文档需要标记
- [ ] 经验教训是否需要更新

## 文档同步时机

1. **Session结束前**：检查并同步相关文档
2. **重大变更后**：更新相关文档的状态
3. **用户要求时**：执行完整的文档同步

## 过期文档处理

- **保留但标记过期**：不删除（有历史参考价值）
- **添加过期标记**：`> ⚠️ 此报告日期为XXXX，部分问题已修复，仅供参考`
- **指向最新来源**：`最新状态请查看MEMORY.md`

## 示例：展示待办

### 错误做法 ❌

从AGENTS.md读取Open Items → 展示过期的待办信息

### 正确做法 ✅

从MEMORY.md读取"待办（SXX最新）"部分 → 展示最新的待办信息

## 常见错误避免

| 错误 | 正确做法 |
|------|----------|
| 从AGENTS.md获取待办 | 从MEMORY.md获取待办 |
| 从PRD获取当前状态 | 从MEMORY.md获取当前状态 |
| 仅凭文件树判断实现状态 | 读取源代码确认实际内容 |
| 采信旧评估报告 | 以最新session记录为准 |
