# Blog内容质量提升方案

## 1. 三大核心要求

| 要求 | 说明 | 解决方案 |
|------|------|----------|
| **架构图/拓扑图** | 每篇技术文章需要配套图表 | SVG图片（零依赖） |
| **去AI化** | 内容像真人写，避免AI味道 | 写作规范 + 人工审核（零依赖） |
| **排版设计** | 大气、吸引人、与网站风格一致 | CSS扩展（零依赖） |

**原则：零收费、零新依赖**

## 2. 架构图/拓扑图方案（零依赖）

### 2.1 图表类型

| 类型 | 适用场景 | 生成方式 |
|------|----------|----------|
| **架构图** | 系统架构、网络拓扑 | SVG图片 |
| **流程图** | 部署流程、迁移步骤 | SVG图片 |
| **对比图** | A vs B 对比 | HTML/CSS |
| **数据流图** | 数据流向、API调用 | SVG图片 |
| **网络拓扑图** | 网络设备连接 | SVG图片 |

### 2.2 SVG图片方案（推荐）

**优势：**
- 零依赖，不需要安装任何npm包
- 已有图片处理流程（Sanity Assets + next/image）
- 矢量图，任意缩放不失真
- 文件小，加载快

**生成工具（免费）：**

| 工具 | 特点 | 网址 |
|------|------|------|
| **Excalidraw** | 手绘风格，免费 | excalidraw.com |
| **Mermaid Live** | 在线渲染，免费 | mermaid.live |
| **Draw.io** | 专业图表，免费 | draw.io |
| **Google Drawings** | 简单易用 | diagrams.google.com |

**工作流程：**

```
1. 用免费工具绘制图表
2. 导出为SVG文件
3. 上传到Sanity Assets
4. 在文章中通过coverImage方式引用
```

### 2.3 图片在文章中的使用

**Sanity Schema已支持：** `coverImage` 字段可存储图片

**前端渲染模式：**
```tsx
// 已有的图片渲染模式，直接复用
<Image
  src={urlFor(image).width(800).url()}
  alt="Architecture diagram"
  width={800}
  height={600}
  className="rounded-xl"
/>
```

**文章中插入图片：**
- 方案A：在Portable Text中直接插入image block（Sanity原生支持）
- 方案B：在文章末尾的`diagrams`数组中存储（需要Schema扩展）

### 2.4 对比表格方案（HTML/CSS）

对于A vs B对比，直接用HTML表格：

```tsx
<table className="my-6 w-full border-collapse rounded-xl overflow-hidden">
  <thead className="bg-gray-100">
    <tr>
      <th className="p-3 text-left">Feature</th>
      <th className="p-3 text-center">Option A</th>
      <th className="p-3 text-center">Option B</th>
    </tr>
  </thead>
  <tbody>
    <tr className="border-b">
      <td className="p-3">Cost</td>
      <td className="p-3 text-center">$$$</td>
      <td className="p-3 text-center">$</td>
    </tr>
  </tbody>
</table>
```

**无需安装任何依赖，直接用现有Tailwind CSS。**

## 3. 去AI化策略

### 3.1 AI写作常见问题

| 问题 | 表现 | 解决方案 |
|------|------|----------|
| **过度正式** | "Furthermore", "In addition" | 使用口语化表达 |
| **结构雷同** | 总是"首先...其次...最后" | 变化句式结构 |
| **缺乏个性** | 没有个人观点 | 加入作者观点和经验 |
| **空洞套话** | "非常重要", "广泛使用" | 用具体数据和案例 |
| **过渡生硬** | 段落间逻辑跳跃 | 自然过渡句 |

### 3.2 写作规范清单

**标题：**
- ❌ "VMware SRM Disaster Recovery: A Comprehensive Guide"
- ✅ "How We Design VMware SRM DR for Philippine Enterprises"

**开头：**
- ❌ "In today's rapidly evolving IT landscape..."
- ✅ "Last month, a healthcare client called us at 2am because..."

**技术描述：**
- ❌ "This solution provides optimal performance"
- ✅ "We saw 40% faster failover after implementing this"

**结论：**
- ❌ "In conclusion, this is a valuable solution"
- ✅ "If you're running VMware and haven't tested DR lately, now's the time"

### 3.3 内容审核清单

每篇文章发布前检查：

| 检查项 | 通过标准 |
|--------|----------|
| 开头是否有具体场景/故事 | ✅ 有真实场景引入 |
| 是否有个人观点/经验 | ✅ 有作者视角 |
| 是否有具体数据/案例 | ✅ 有量化指标 |
| 是否有"首先/其次/最后"套话 | ❌ 无套话 |
| 是否有"Furthermore/Moreover" | ❌ 无正式连接词 |
| 是否有空洞形容词 | ❌ 无"非常重要"等 |
| 结尾是否有行动建议 | ✅ 有具体下一步 |
| **语言一致性** | ✅ 英文无中文混杂，中文无英文混杂 |

#### 语言一致性检查规则

| 语言 | 允许 | 禁止 |
|------|------|------|
| **英文文章** | 技术术语（VMware, FortiGate等） | 中文标点、中文字 |
| **中文文章** | 技术术语（VMware, FortiGate等） | 英文标点、英文句子 |

**检查方法：**
```bash
# 检查英文文章中的中文字符
grep -P '[\x{4e00}-\x{9fff}]' article-en.md

# 检查中文文章中的英文句子
grep -P '[A-Za-z]{10,}' article-zh.md
```

**例外：**
- 产品名称（VMware, Sangfor, FortiGate等）
- 技术术语（API, SDK, HTTP等）
- 代码片段
- 人名、公司名

### 3.4 Humanizer处理流程（零依赖）

1. **初稿生成**：AI生成内容框架
2. **人工润色**：按写作规范逐条修改
3. **语法检查**：人工检查或浏览器插件（不安装新依赖）
4. **可读性检查**：人工判断，确保口语化、有个性

**不安装任何付费或免费工具，完全靠人工审核。**

### 4.2 文章内容组件设计

#### Callout Box（提示框）

```tsx
// 三种类型：info, warning, tip
<div className="my-6 p-4 rounded-xl border-l-4 bg-blue-50 border-blue-500">
  <div className="flex items-center gap-2 text-blue-700 font-medium mb-2">
    <Info size={18} /> Key Takeaway
  </div>
  <p className="text-blue-800">Content here...</p>
</div>
```

#### Code Block（代码块）

```tsx
<div className="my-6 rounded-xl overflow-hidden">
  <div className="flex items-center justify-between px-4 py-2 bg-gray-800 text-gray-400 text-sm">
    <span>{language}</span>
    <button onClick={copyCode}>Copy</button>
  </div>
  <pre className="p-4 bg-gray-900 text-gray-100 overflow-x-auto">
    <code>{code}</code>
  </pre>
</div>
```

#### Comparison Table（对比表格）

