# 三任务综合评估计划 v4（最终版）

## 框架

### DevOps角色分工

| 角色 | 担当 | 职责 |
|------|------|------|
| 开发者 | Agent | 评估、发现问题、修复代码/内容 |
| 测试者 | Agent | 修复后自测（lint/typecheck/build/test），确保代码健康 |
| 运维者 | Agent | 验证可运维性，确保无屎山代码 |
| 业务验收者 | 用户 | 确认业务准确性、最终批准 |

### 自测循环（核心）

每次修复后必须执行自测循环，直到通过才交付：

```
修复代码 → npm run lint → npm run typecheck → npm run build → npm run test
    ↑                                                          ↓
    ←←←←←←←←←←←← 发现问题则回到修复 ←←←←←←←←←←←←←←←←←←←←←←←←
                                                    全部通过 → 交付
```

**自测命令**:
| 命令 | 检查内容 | 失败处理 |
|------|----------|----------|
| `npm run lint` | 代码规范、潜在错误 | 修复后重新lint |
| `npm run typecheck` | TypeScript类型安全 | 修复类型错误 |
| `npm run build` | 构建是否成功、42页面是否正常 | 修复构建错误 |
| `npm run test` | 单元测试（Vitest 49/49） | 修复测试 |

**不通过则不交付** — 代码必须通过全部自测才算健康。

### 核心约束

1. 评估必须用工具，不能手动判断
2. 厂商信息必须去官网查询，禁止幻想
3. 不破坏双故事线（Build.Run.Protect. + AI旅程）
4. 每个任务必须跑完闭环：评估→修复→自测→验收
5. 每个维度只分配一个主工具，不存在两个工具评同一件事
6. 修复后必须自测（lint/typecheck/build/test），不通过不交付

### 评分标准

| 分数 | 含义 |
|------|------|
| 4 | 优秀，无需改进 |
| 3 | 良好，小问题不影响体验 |
| 2 | 需改进，明显问题 |
| 1 | 严重问题，必须立即修复 |

**达标**: 所有维度平均分≥3.0，且无1分维度
