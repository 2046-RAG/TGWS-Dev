**Project:** TGWS (TechGuru Network & Data Solutions) Corporate Website
**Audit Date:** 2026-07-29
**Auditor:** MiMoCode Code Audit Expert (6 parallel review subagents)
**Scope:** All files under `tgws/src/` and `tgws/sanity/` (~120 source files)
**Method:** Static source review — read every file before claiming a defect (AGENTS.md Rule #36), list ALL defects (Rule #54), exhaust all aspects at once (Rule #56). No fixes were applied.

## 1. Executive Summary

**Overall Code Quality Score: 62 / 100**

The TGWS codebase is feature-complete and broadly functional, but it carries meaningful **security debt** and **type-safety drift** that warrant a structured remediation pass before it can be considered production-hardened.

| Dimension | Assessment |
|---|---|
| Functionality | Good — pages render, API routes return data, i18n works for the primary locale |
| Security | **Weak** — unhandled error logging, input validation gaps, missing auth enforcement, XXS/HTML-injection surface |
| TypeScript safety | **Moderate** — strict mode is on, but pervasive `as string` casts, `any` in Sanity/Ticket schemas, `NodeJS.Timeout` misuse in browser |
| React/Next.js hygiene | Moderate — hydration-mismatch risks from render-time `new Date()`/`window`, effect dependency issues, duplicate theme logic |
| Accessibility | **Weak** — recurring missing labels/roles on icon-only buttons, modals/overlays, no focus traps, contrast issues |
| i18n coverage | **Moderate** — next-intl is wired up but ~30+ components bypass it with hardcoded English strings |
| Sanity integration | Moderate — GROQ results consumed unvalidated, draft-handling absent, server/browser client boundary not enforced |
| Tests | **Weak** — API integration tests are tautological (assert mocks return mocked values), no error-path coverage |

### Top 3 Risks (ordered by blast radius)

1. **CRITICAL — API error-handling baseline is broken.** Of 12 API route handlers, **10 do not use `logServiceError`** (violating the project's own architectural rule) and **8 have no `try/catch` at all**. Production failures are currently silent and surface as opaque 500s with Postgres internals leaked to the client (contact, tickets, tickets/[id], upload, reset-password all `return error.message`). This is the single highest-leverage fix.

2. **CRITICAL — Admin authorization is client-only and incomplete.** The `/support/admin` dashboard verifies a user is logged in but **never checks the admin role**; `support/page.tsx` hardcodes `isAdmin={true}` for every authenticated user. The middleware refreshes sessions but gates no protected route. Any logged-in user can read all ticket stats and batch-update ticket statuses. This must be enforced server-side.

3. **CRITICAL — Input-validation + rate-limiting + CSRF are absent on all public mutating endpoints.** `/api/contact`, `/api/search`, `/api/search/lead`, `/api/auth/reset-password`, `/api/upload` accept unvalidated bodies (no zod), have **no rate limiting** (enabling email-quota exhaustion, API-cost amplification, and DoS), and **no CSRF protection** (forged cross-site POSTs can create tickets/leads on a logged-in user's behalf). The file-upload route additionally has a MIME-whitelist bypass, filename path-traversal, and serves PII attachments via public URLs.

## 4. Recommendations & Remediation Path

**Phase 1 — Critical baseline (fast wins, highest impact):**
1. AUDIT-001/002/003: Add `try/catch` + `logServiceError` to every API route (~1 day). Resolves the architectural rule violation for 10/12 routes.
2. AUDIT-004: Stop leaking `error.message` to clients (contact, tickets, tickets/[id], upload, reset-password). One-line generic-message substitution per route.
3. AUDIT-117/118/201: Enforce admin role server-side — add `requireAdmin()` server helper (AUDIT-224) and a `/support/admin/layout.tsx` guard.
4. AUDIT-010/011: Install a centralized rate-limiter + CSRF/`Origin` check on all public mutating endpoints.

**Phase 2 — High-severity cleanup:**
5. AUDIT-046/008: Add `escapeHtml` helper; escape all user-content before email/HTML interpolation (resend.ts, search/lead).
6. AUDIT-145/146/147: Fix `JsonLd` `</script>` escape, remove `picsum.photos` defaults (Rule #58), replace QRCode third-party API.
7. AUDIT-012/013/014/015: Harden `/api/upload` (magic-byte validation, filename sanitization, signed URLs, ownership-before-upload, require `ticketId`).
8. AUDIT-160/161/162/164/166: Accessibility — modals/dialogs get `role="dialog"` + focus traps + Escape; LeadCaptureForm gets labels; paste-screenshot `<div>` gets `role`/`tabIndex`; DarkModeToggle gets arrow-key nav.
9. AUDIT-029/031: Add draft filtering + projection validation to Sanity GROQ queries (search, tco, products).
10. AUDIT-198/199/200: Fix hooks — restore-on-mount ordering, optimistic rollback snapshot, offline-cache try/catch.

**Phase 3 — Consolidation & i18n coverage:**
11. AUDIT-221/223/224/225: Implement shared helpers (`useLocale` base, `useTheme`, `requireAdmin`, `products/shared.ts`).
12. AUDIT-095/100/137/183/185: Move hardcoded English strings into `messages/{en,zh}.json` per namespace (home, products.detail, solutions, tco, nav, footer, userMenu, ticketList, cookieConsent).
13. AUDIT-075: Make `Breadcrumb` auto-prefix hrefs + localize labels (resolves ~8 findings at once).
14. AUDIT-202: Rewrite the API integration tests to actually invoke handlers with `NextRequest`.

**Phase 4 — Low-severity polish (opportunistic):**
15. Type annotations, `NodeJS.Timeout` fixes, dead-code removal, contrast tweaks, `aria-hidden` on decorative icons.
